# 04. 組織ルールと Project ルールの関係

この章の機能は組織 Workspace 専用です。現在確認できる個人 Workspace では「組織ルール」と「ルールの関係」はナビゲーションに表示されず、関係 URL を開いても Workspace 概要へ戻ります。そのため、この章は画面ソース、resolver 実装、既存テスト仕様に基づく説明で、2026-10-14 の環境では新しい関係を作成していません。

## 4.1 resolution とは

同じ Project に組織ルールと Project ルールがあるとき、RuleBranch は Repository に適用するルール集合を解決します。これを resolution と呼びます。

明示的な関係がなくても、selector を満たす有効な組織ルールと Project ルールは既定で両方採用されます。画面に架空の `inherit` 関係は作成されません。「関係の種類」に `inherit` や `allow` という選択肢もありません。

## 4.2 関係の種類

| 画面表示 | 内部値 | 解決結果 |
|---|---|---|
| 置換 | `override` | Project 子ルールを採用し、組織親ルールを除外する |
| 追加(強化) | `extend` | 組織親ルールと Project 子ルールを両方採用する |
| 不適用 | `deny` | 組織親ルールを除外し、Project 子ルールを採用する |

「必須（組織）」の親ルールには「追加(強化)」だけを設定できます。「置換」と「不適用」は、必須方針を下位 Project から無効化するため拒否されます。

## 4.3 関係を作成する

組織 Workspace の左ナビゲーションから「ルールの関係」を開き、「関係を作成」を押します。

1. `ルールを検索` で対象を絞り込みます。
2. `親ルール` に組織ルールを選びます。
3. `子ルール` に Project ルールを選びます。
4. `関係の種類` で「置換」「追加(強化)」「不適用」を選びます。
5. 「不適用」では `不適用にする理由` を入力します。
6. 内容を確認し、「関係を作成」を確定します。

不適用理由は必須で、2,000文字以内です。関係一覧には親、子、Project、関係、理由、検証状態が表示されます。検証状態は「未検証」「検証済」「検証失敗」です。

## 4.4 選択と検証の制約

- 親候補は組織スコープ、子候補は Project スコープです。
- 親子を逆にしたり、organization 同士、project 同士を関係付けたりできません。
- 同じ子 Rule に二重の関係は作成できません。
- 必須（組織）の親への置換・不適用は作成できません。
- 関係の作成だけでは Rule 本体や Version の状態は変わりません。
- 現行 UI は関係の削除をサポートしていません。
- 閲覧者は一覧を閲覧できますが、「関係を作成」は表示されません。

## 4.5 生成結果を確認する

関係を作った後は、対象 Project の「反映状況」で Repository の「生成ファイルを作成・更新」を実行します。ジョブが完了したら、Draft PR の生成物で次を確認してください。

- 明示関係なし: 親と子の両方が含まれる
- 置換: 子が含まれ、親が除外される
- 追加(強化): 親と子の両方が含まれる
- 不適用: 子が含まれ、親が除外される

RuleBranch が Draft PR を作っても自動マージはしません。GitHub で差分を確認し、人間がマージした後、RuleBranch の「反映状況」で検証済みになることを確認します。

## 4.6 利用できない場合

「ルールの関係」が表示されない場合は、まず Workspace が個人か組織かを確認してください。個人 Workspace にはこの機能はありません。組織 Workspace でも作成操作が表示されない場合は、メンバー以上の書込み権限があるか管理者へ確認してください。


未実行部分の構造と解決規則は、[データモデル](../design/04-data-model.md)と[ルールのライフサイクル](../design/05-rule-lifecycle.md)を参照してください。
